Linux 系统监控与进程管理 - 上手操作练习题 (共18题)

基于 Chapter 08（系统监控和性能优化）和 Chapter 09（进程管理）知识点设计，所有题目均可在实际Linux系统上操作验证

🎯 真实场景背景

你是某电商平台的运维工程师。周二上午10:15，监控系统突然告警：订单数据库服务器的CPU使用率持续超过90%，网站响应速度明显变慢。部门经理要求你立即登录服务器排查问题，找出性能瓶颈并恢复服务。

这次故障排查任务将用到本章学习的所有系统监控和进程管理知识——从查看系统负载、分析CPU/内存使用，到定位异常进程和处理系统服务。

✅ 练习说明

  • 请按要求依次完成各练习。完成后在学习通内打开问卷填写并提交。
  • 本次练习不需要联网，所有操作都可以在本地服务器完成。
  • 可以使用普通用户账号执行大部分操作，需要管理员权限时使用sudo。
  • 注意观察每个命令的输出结果，不要只执行命令不看输出。

📋 基础操作篇 (第1-9题)

第1题

题目: 使用 uptime 命令查看系统的当前时间、运行时长和负载平均值，记录下过去1分钟、5分钟、15分钟的负载值。

第2题

题目: 使用 lscpu 命令查看服务器的CPU信息，记录下CPU核心数和线程数。

第3题

题目: 使用 free -h 查看系统内存使用情况，记录总内存、已用内存和可用内存的数值。

第4题

题目: 使用 df -h 查看各分区磁盘空间使用情况，找出使用率最高的分区并记录其挂载点和使用率。

第5题

题目: 使用 ps aux 查看当前系统中所有运行的进程，记录下PID为1的进程名称。

第6题

题目: 使用 pstree -p 查看进程树结构，找出PID为1的进程下有多少个子进程。

第7题

题目: 执行 top 命令进入实时监控界面，按下 P 键按CPU排序、按下 M 键按内存排序，观察排序变化后按 q 退出。

第8题

题目: 使用 netstat -tuln 查看系统当前监听的TCP和UDP端口，记录下所有处于LISTEN状态的端口号。

第9题

题目: 使用 journalctl -p err 查看系统错误级别的日志，记录最近3条错误日志的内容。

🚀 进阶操作篇 (第10-15题)

第10题

题目: 使用 top -b -n 1 以批处理模式执行一次top命令，将输出结果保存到 top_output.txt 文件中，然后使用 grep 查找文件中CPU使用率最高的进程。

第11题

题目: 使用 ps aux --sort=-%cpu | head -5 找出CPU占用最高的前5个进程，记录它们的PID、CPU使用率和命令名。

第12题

题目: 使用 ps aux --sort=-%mem | head -5 找出内存占用最高的前5个进程，记录它们的PID、内存使用率和命令名。

第13题

题目: 使用 pidstat 1 3 监控系统进程的CPU使用情况（每隔1秒采集一次，共采集3次），观察并记录CPU使用率最高的进程名及其PID。

第14题

题目: 使用 find / -type f -size +100M 2>/dev/null 查找系统中大于100MB的大文件，记录这些文件的路径和大小。

第15题

题目: 使用 systemctl status 查看某个系统服务的运行状态（例如 sshd 或 cron），记录服务当前是否处于 active (running) 状态。

🏆 挑战操作篇 (第16-18题)

第16题

题目: 模拟故障排查场景——执行 cat /dev/urandom > /dev/null & 让一个进程在后台持续消耗CPU，然后：

  1. 使用 top 找出这个CPU占用高的进程PID
  2. 使用 kill 终止该进程
  3. 使用 ps aux | grep 验证进程是否已被终止

第17题

题目: 写一条组合命令，一次性输出以下系统运行状态报告（要求使用命令替换和管道）：

==== 系统运行状态报告 ====
系统负载:  [uptime的负载值]
CPU核心数: [lscpu中的核心数]
内存使用:  [free -h中的内存使用情况]
磁盘使用:  [df -h中根分区的使用率]
运行进程数: [ps aux的进程总数]
监听端口:  [netstat -tuln中LISTEN的端口数]
===========================

第18题

题目: 模拟完整的性能诊断流程——使用本章所学的系统监控命令，完成以下操作：

  1. 使用 uptime 查看系统负载
  2. 使用 free -h 查看内存使用
  3. 使用 df -h 查看磁盘使用
  4. 使用 pidstat -urd 1 3 同时监控CPU、内存和I/O
  5. 使用 journalctl -p err --since "1 hour ago" 查看最近1小时的错误日志 将所有输出结果按顺序重定向到一个名为 diagnosis_report.txt 的文件中。

💡 思考题

  1. 当系统负载很高但CPU使用率不高时，可能是什么原因导致的？如何进一步排查？
  2. top 命令中的 %CPU 和 %MEM 两个指标，在生产环境中分别应该关注什么阈值？
  3. 使用 kill -9 强制终止进程有什么风险？在什么情况下才应该使用它？
  4. 为什么需要同时监控CPU、内存、磁盘I/O和网络这四个维度的指标？它们之间有什么关联？
  5. 僵尸进程是如何产生的？如何预防和清理僵尸进程？
